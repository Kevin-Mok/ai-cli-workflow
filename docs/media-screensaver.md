# Three-monitor media screensaver

Show a media conveyor across the existing X11/i3 desktop without changing display configuration. Install the launcher, preview it, and start the idle monitor. Automatic playback starts after five minutes without keyboard/mouse input or visible motion on the middle 4K screen; the i3 bar is excluded. Chrome extensions are not required.

## Requirements and installation

Use an X11 desktop with exactly three horizontally arranged outputs and XInput2.1 support. Automatic activation requires a middle output at least 3840×2160. The launcher reads live `xrandr --listmonitors` geometry, including vertical offsets; it never calls the display-layout script or disables an output. The older `dual-monitor-slideshow` entrypoint remains unchanged and retains its older behavior.

Required Ubuntu packages: `python3`, `python3-gi`, `python3-gi-cairo`, `gir1.2-gtk-3.0`, `gir1.2-gstreamer-1.0`, `gstreamer1.0-gtk3`, `gstreamer1.0-plugins-good`, `gstreamer1.0-plugins-bad`, `gstreamer1.0-libav`, `python3-xlib`, `python3-pil`, `libxi6`, `libxss1`, `x11-xserver-utils`, and ImageMagick with HEIC reading support. The synthetic demo additionally uses `ffmpeg`. Package installation requires sudo; the screensaver installer and runtime do not.

From the checkout, run `./scripts/executable_media-screensaver install`. This copies the package and launcher into `~/scripts/`, creates `~/scripts/media-screensaver-native`, and writes the native-host manifest under both Chrome and Chromium's per-user `NativeMessagingHosts` directories. Re-running updates only the owned package files and preserves other files in that directory. Nonstandard browser configurations need the same native-host manifest in their documented host lookup location.

The installer writes `~/.config/systemd/user/media-screensaver.service` and replaces only its old direct-daemon i3 startup line with `~/scripts/media-screensaver service`, preserving other settings. Run `refresh-config` after tracked configuration changes, then run the explicit installer because refresh excludes scripts. Run `~/scripts/media-screensaver service` from the desktop to start now. It reloads the user manager, imports the current X11 display/authentication/session environment and starts the service. Each i3 login runs the same command; the unit deliberately is not enabled at `default.target`, where the desktop environment may be unavailable. No sudo is needed.

The service runs the existing idle monitor and restarts it after five seconds if it exits. Inspect it with `systemctl --user status media-screensaver.service` or `journalctl --user -u media-screensaver.service -n 20 --no-pager`. Stop it with `systemctl --user stop media-screensaver.service`; restart with `systemctl --user restart media-screensaver.service`. A deliberate stop stays stopped until the next service start or i3 login. The daemon reports readiness or suppression every 30 seconds in the journal. Before migrating an already-running foreground daemon, stop it with Ctrl+C; duplicate prevention permits only one idle monitor. Service restarts reset the five-minute activity clock. While running, the service holds a connection-scoped X11 blanking/DPMS inhibitor so the server cannot turn displays black before or during Hevin playback. It clears an already active server blank on startup and releases inhibition on exit without changing your configured timeouts. Deliberate screen-off requests, explicit lockers and suspend retain control. The blackout shortcuts stop this service before powering displays off.

## Daily 10:00 AM schedule

Update the installed launcher with `./scripts/executable_media-screensaver install`, then run `./scripts/executable_setup-screensaver-timer` from your X11 desktop terminal. Neither command needs sudo. The installer checks that the installed launcher supports scheduled playback, writes only `media-screensaver-daily.service` and `.timer` under the systemd user configuration directory, imports the current display/session environment, reloads systemd and enables the timer. Re-running updates those same units.

The timer launches at **10:00 AM in the machine's local timezone**, within roughly one second. It powers the displays on and starts the five-minute idle service before attempting scheduled playback. The desktop must be logged in. It does not wake the computer: a timer due during suspend may launch on resume. Runs missed while powered off or with the timer inactive are not caught up (`Persistent=false`). Later i3 logins refresh the display environment through the existing `media-screensaver service` startup command. A shared playback lock prevents simultaneous daily, idle and manual previews.

Use fish abbreviation **`sofss`** to turn the displays off now until the next 10:00 AM launch. It expands to `~/linux-config/scripts/executable_setup-screensaver-timer --black-until-10`. The command arms the daily timer first, stops idle and daily playback, enables DPMS and powers the displays off. At 10 AM the daily service powers them on and resumes idle monitoring; locked sessions still suppress playback. Normal keyboard/mouse input can wake displays early, as with `sof`. After 10 AM, the next launch is tomorrow; the daily schedule remains enabled afterward. This does not arrange a blackout at every computer startup. Already-running manual previews should be dismissed before using it. No sudo is needed. Existing fish shells can load the abbreviation with `source ~/.config/fish/key_abbr.fish`.

Use **`sofs HOURS`** for a delay instead: `sofs 2` keeps displays off until playback starts two hours later; `sofs 0.5` waits thirty minutes. The abbreviation expands to `~/linux-config/scripts/executable_setup-screensaver-timer --delay-hours`, followed by your argument. Positive finite hours are required; missing, zero, negative and nonnumeric values are rejected before changing anything. Repeating the command replaces the pending launch and restarts the full delay. This replaces the daily schedule with a one-shot timer that is not enabled at login; reboot cancels it. Run `sofss` or the installer with no mode flag to restore daily 10 AM scheduling, or `--disable` to cancel the pending launch. The computer must stay awake; this cannot wake it from suspend. Input may wake displays early. Dismiss any manual preview first. `ss` remains immediate playback.

To test the wake sequence immediately, run `~/linux-config/scripts/executable_setup-screensaver-timer --test`: displays turn off for ten seconds, wake, then show a manual screensaver preview. Input dismisses playback. This leaves the daily timer unchanged and wakes displays if the wait is interrupted.

The `scheduled` command skips locked sessions and uses manual-preview browser behavior, without waiting five idle minutes. Missing browser coverage does not dismiss the daily preview; the separate idle daemon still requires healthy browser coverage. A newly detected middle-screen video or keyboard/mouse input dismisses playback normally. Scheduled playback clears an already active X11 blank screen, then holds a connection-scoped XScreenSaver 1.1 inhibitor to prevent automatic screen blanking and DPMS sleep. Cleanup, exceptions or process exit release it without changing your configured timeouts; explicit lockers and forced power requests retain control. The computer must remain awake. Inspect the next run with `systemctl --user list-timers --all media-screensaver-daily.timer`; inspect playback with `journalctl --user -u media-screensaver-daily.service -n 20 --no-pager`. Test a launch from the unlocked desktop with `systemctl --user start media-screensaver-daily.service`.

Disable future daily launches with `./scripts/executable_setup-screensaver-timer --disable`. This leaves already-running playback alone; dismiss it with input or stop `media-screensaver-daily.service`. Installer options `--plain` (or `CLI_PLAIN=1`) and `--details` control ASCII output and raw errors. Regression tests: `python3 -B -m unittest discover -s tests -p test_screensaver_timer.py`.

## Local screen motion detection

The idle service compares small grayscale samples of the middle 4K monitor in memory. Visible i3bar windows are located from their actual X11 geometry, including nested i3 frames, and masked before comparison. Clock, network, music and workspace changes in that bar do not reset the quiet timer. Movement elsewhere on the 4K monitor resets its five-minute quiet interval; changes on side monitors do not. Keyboard or mouse activity has its own five-minute clock, and both must be quiet before launch.

No screenshots are saved or uploaded. Sampling stops during owned screensaver playback so the conveyor does not count as desktop activity. Physical input dismisses playback; the next quiet interval starts after dismissal. A changed monitor/bar layout, unavailable capture or locked/unknown session suppresses activation and restarts the interval. `status` reads the running monitor's current motion result, not browser coverage. Restarting the service resets both clocks.

Screen motion approximates playback: non-bar animations can keep the desktop awake, while a still scene or very small/subtle changes can be missed. The detector accumulates gradual differences against its retained baseline, while ignoring tiny changes such as a text caret. It cannot see movement hidden behind another window. It does not monitor sound. Explicit `ss`, `sofs HOURS` and daily schedules remain available independently.

## Optional browser bridge for manual previews

Automatic idle activation does not need this extension. The retained bridge can dismiss a manual or scheduled preview when newly playing browser video appears on the middle monitor; unavailable coverage does not block those explicit previews.

To use it, open `chrome://extensions` in each Chrome/Chromium profile, enable Developer mode, choose **Load unpacked**, and select `~/scripts/media_screensaver/browser`. Its ID is `fpologomejgfmlemideffbaallaejhbb`. Enable incognito/file access only if needed, reload normal web pages, and switch away from protected Chrome settings tabs. The native host alone does not load the extension. It reports playback geometry locally without URLs, page titles or media names; private runtime snapshots expire after four seconds.

## Daily commands

Press **Alt+Shift+S** (left Alt is keycode 64) or **Super+Shift+S** in i3, or use the fish abbreviation `ss` (expands to `~/scripts/media-screensaver preview`), for immediate playback, including when the browser bridge is unavailable. The i3 binding starts on key release so the shortcut itself does not immediately dismiss playback. Existing fish shells can load abbreviations with `source ~/.config/fish/key_abbr.fish`. Run `~/scripts/media-screensaver preview` for the real media library at `/mnt/linux-files-3/hevin`. Use `--media DIR` for another recursive library. Supported extensions are JPG/JPEG, PNG, WebP, HEIC, MP4, MOV and MKV, case-insensitively. Symbolic links and unrelated files are ignored. Originals are opened read-only. Individual corrupt/unavailable files are skipped and quarantined until the preview restarts; an unavailable mount or no decodable media produces an actionable error.

Each launch immediately fills all three outputs with random photos/videos from the selected library. Every ten seconds, a new random item enters on the left and existing items move one output right with a 750ms slide. The same video pipeline survives movement and resizing; short clips seek to the start at end-of-stream, and long clips stop when their card exits. Video audio is disabled. Photos and videos preserve their aspect ratio against black. Videos automatically honor embedded orientation tags; absent metadata leaves their pixels unchanged. Adjacent selections differ whenever another usable file exists; a one-file library repeats that file on all three outputs. Each launch draws afresh; random selection can repeat a previous launch.

Run `~/scripts/media-screensaver daemon` for activation after 300 seconds of keyboard/mouse inactivity. It tracks raw XInput2 keyboard/mouse activity from daemon startup, ignoring software screensaver resets from players, without resetting the physical-input clock or taking input grabs. The running service temporarily inhibits automatic X11 blanking/DPMS, preserving configured timeouts; explicit lock/suspend still retain control. Locked sessions and unavailable lock state suppress activation. Any keyboard/mouse activity dismisses a preview. Automatic playback uses the local motion policy and does not require Chrome coverage. The optional browser gate remains available to manual previews. Stop the foreground daemon with Ctrl+C; it releases its owned preview. For normal background use, start `service` and stop it with `systemctl --user stop media-screensaver.service`. Never kill unrelated players or browser processes.

Run `~/scripts/media-screensaver probe --media DIR` to decode one frame of every supported candidate and report per-format successes/skips. It does not start a preview or alter originals. It can take time for a large library; use a small test directory first. `~/scripts/media-screensaver demo` generates disposable portrait photos and short/long videos, probes them plus a corrupt MP4, then fills all three outputs with its long synthetic video for 35 seconds. The demo does not generate HEIC because the installed libheif has reading support but no HEVC encoder plugin.

## Review video orientation

Run `~/scripts/media-screensaver orient` to choose a video, review it in a separate window, and save an additional rotation if needed. The chooser starts in the configured media library; `--media DIR` selects another starting directory. Use `~/scripts/media-screensaver orient --file '/absolute/path/problem.mov'` to open a known file directly, including paths containing spaces.

The video loops silently. **Rotate left 90°** and **Rotate right 90°** turn the displayed picture; two clicks turn it 180°. The current additional clockwise correction appears below the picture. **Use metadata** resets that correction to zero; **Save** commits it and closes the window, while **Cancel** or closing the window leaves saved data unchanged. Keyboard and mouse activity do not dismiss this review window. A decoder or save error stays visible so you can cancel or correct the issue.

Corrections live only in `$XDG_CONFIG_HOME/media-screensaver/orientation.json` (default `~/.config/media-screensaver/orientation.json`), with a private directory and file. Records contain absolute path, size, nanosecond modification time and additional clockwise degrees. Updates are validated, locked and atomic, preserving other entries. Changed files ignore stale corrections; files changed during review must be reopened before saving. Renamed files need review again. Invalid saved data produces a warning and prevents saving until you repair or move that JSON; it is never silently overwritten. New screensaver cards read the saved correction, so restart a preview to update an already-visible card. Originals are never rewritten; no width/height or image-analysis guesses are made.

Options shared by commands: `--seconds N` bounds preview duration (0 waits for dismissal); `--report PATH` writes a new private JSONL preview report with item IDs, slots and playback timestamps, never personal filenames; `--plain` produces ASCII CLI output (`CLI_PLAIN=1` also works); `--details` includes raw diagnostics. `--help` describes the commands. Report paths must not already exist. `NO_COLOR` does not remove emojis; output does not require ANSI color.

## Verification and limitations

Automated and observed desktop evidence are recorded separately in [the original implementation plan](../plans/monitor-media-screensaver.md), [orientation plan](../plans/screensaver-video-orientation.md) and [screen motion plan](../plans/screensaver-screen-motion.md). Repeatable manual checks, including browser geometry and cleanup, live in [the smoke checklist](smoke-tests.md#media-conveyor-screensaver).

Browser page zoom is supported on X11. Uniform browser UI scale (including the measured 1.40625 scale) is converted into native X11 pixels and checked against real window bounds. Unreconciled mixed display scaling, ambiguous transforms/CSS zoom, noncenter video positioning, picture-in-picture, restricted browser tabs, inaccessible frames and incomplete snapshots make the optional browser gate unavailable. Canvas/WebCodecs renderers without an HTML video element are not detectable. The bridge is for Chrome/Chromium; it cannot distinguish playing video in other browsers. Custom Chrome builds/host lookup paths and site-specific players require separate acceptance. These browser limitations apply only to the optional manual-preview gate; automatic activation uses screen motion. i3 may ignore conventional browser minimize requests; a still-viewable playing video continues to block. Moving an owned browser to a non-viewable i3 workspace/scratchpad excludes its video after native window reconciliation.

The CPU GTK video sink prefers installed libav decoders to avoid incompatible CUDA-memory negotiation. Video widgets bypass GTK3's double buffering on X11 to avoid black regions when photos and videos share the conveyor. This is a tested legacy rendering workaround; the GTK API is deprecated and warrants rechecking during a renderer upgrade. High-resolution simultaneous videos may consume significant CPU; smoothness must be checked on the actual GPU/desktop. No personal images or videos are committed. Roll back by stopping `media-screensaver.service`, removing its unit and i3 startup line, running `systemctl --user daemon-reload`, and uninstalling the named package/host manifests; the old slideshow and existing lock/suspend configuration remain available.

## Automated and manual test plan

Automated: `SCREENSAVER_MOTION_X11_TEST=1 xvfb-run -a python3 -B -m unittest discover -s tests -p 'test_media_screensaver*.py' -v` exercises the conveyor, strict native framing/state, complete native-window matching, installation, real GStreamer continuity/loop/cleanup, metadata/correction corner pixels, private persistence/reset/cancel/stale/malformed records, portrait pixels, software idle resets, keyboard grabs and manual bridge failure. `node tests/test_media_screensaver_browser.cjs` runs real content-script initialization plus geometry, frame relay, shadow roots, UI scale and audio-only regressions. `bash tests/test_desktop_display_layout.sh` checks existing display integration. These require no sudo; an environment blocking X11 sockets needs its approved scoped execution route even for Xvfb.

Manual: follow the grouped smoke entries for the full35-second conveyor, browser matrix, unavailable mount/corruption and five-minute activation. A real suspend/resume cycle and five uninterrupted idle minutes are separate acceptance checks; automated threshold/cleanup evidence does not establish those observations. Browser tests in an isolated profile do not enable the extension in ordinary user profiles.
